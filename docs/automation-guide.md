# Автоматизация на Playwright

## Состав набора

- `tests/api/products.spec.js` — настоящие HTTP-запросы к Fake Store API; запуск требует интернета.
- `tests/ui/store.spec.js` — UI-тесты демонстрационного магазина. Запрос на каталог подменяется фиксированным JSON, чтобы тесты не зависели от внешней сети и меняющихся данных.
- `playwright.config.js` — настройки тестового раннера, браузера, отчёта и локального web-сервера.
- `scripts/static-server.js` — небольшой сервер на встроенном модуле Node.js, который отдаёт файлы репозитория по HTTP.

## Установка

Требуется поддерживаемая версия Node.js (рекомендуется LTS).

```bash
npm install
npx playwright install chromium
```

## Команды

```bash
npm test           # UI + API; API-сценарии требуют интернет
npm run test:ui    # воспроизводимые UI-тесты с подменой API-ответа
npm run test:api   # запросы к внешнему Fake Store API
npm run test:headed # UI в видимом браузере
npm run test:report # открыть последний HTML-отчёт
```

По завершении Playwright создаёт HTML-отчёт в `playwright-report/`. При неудаче сохраняются скриншоты и трассировка согласно конфигурации.

## Почему UI-тесты используют mock

Интерфейс тестируется с заранее заданными тремя товарами. Это делает результаты стабильными: в тесте известно, какие названия и цены должны отобразиться. Mock API означает, что эти UI-тесты проверяют работу интерфейса и его логику, а не доступность реального Fake Store API. Для проверки самого API предусмотрен отдельный файл в `tests/api/`.

## Что проверяет UI-набор

1. Отрисовка товаров из ответа каталога.
2. Поиск по части названия без учёта регистра.
3. Поиск без совпадений.
4. Сортировка по цене по возрастанию и убыванию.
5. Сброс поиска и сортировки.
6. Добавление товара и увеличение количества.
7. Уменьшение количества до удаления из корзины.
8. Сохранение корзины после перезагрузки.
9. Понятная ошибка при HTTP 503 от каталога.

## CI

GitHub Actions запускает детерминированные UI-тесты при push и pull request. API-тесты к внешнему сервису оставлены отдельной командой, чтобы кратковременная недоступность стороннего API не делала UI-проверки нестабильными.

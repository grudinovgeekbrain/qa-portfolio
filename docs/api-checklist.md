# API testing cheat sheet

Используй как универсальную карту проверок, но выбирай только проверки, которые имеют смысл для конкретного endpoint и подтверждены контрактом API.

## Универсальная проверка любого запроса

| Что | Что проверить | Пример вопроса |
|---|---|---|
| Метод и URL | Правильный HTTP-метод и endpoint | Отправляю ли я GET на ресурс списка? |
| Статус | Код соответствует сценарию | Ожидается ли 200 для успешного GET? |
| Заголовки | Content-Type, Accept, нужные служебные заголовки | Вернулся ли JSON? |
| Формат тела | JSON object, array, строка или пустое тело — согласно контракту | Должен ли `/products` вернуть массив? |
| Обязательные поля | Поля существуют | Есть ли `id`, `title` и `price`? |
| Типы | Типы полей соответствуют контракту | `price` — число, а не строка? |
| Значения | Диапазоны, допустимые значения, не пустые обязательные поля | Цена неотрицательная, если таково правило? |
| Ошибки | Некорректный запрос обрабатывается по контракту | Что происходит при отсутствующем поле? |
| Время ответа | Сравнить с установленным SLA/требованием | Есть ли согласованный лимит? |
| Доказательства | Сохранить фактический результат | Есть ли скриншот Postman или отчёт автотеста? |

## Проверки по HTTP-методам

| Метод | Успешный сценарий | Что дополнительно проверить |
|---|---|---|
| GET | Данные получены | Фильтры, сортировка, пагинация, пустая выборка, схема ответа |
| POST | Ресурс создан или операция принята | Переданные значения, ID, дубли при повторной отправке, правила валидации |
| PUT | Ресурс целиком обновлён | Все заменяемые поля, состояние не изменённых ресурсов |
| PATCH | Отдельные поля изменены | Изменились только указанные поля, остальные сохранены |
| DELETE | Ресурс удалён согласно контракту | Ответный статус, состояние после удаления, повторный DELETE если определено контрактом |

## Типичные статусы — не универсальные ожидания

| Код | Общее значение | Когда может встретиться |
|---:|---|---|
| 200 | Успешный запрос | Получение или обновление с телом ответа |
| 201 | Создано | Ресурс создан |
| 202 | Принято в обработку | Асинхронная операция ещё выполняется |
| 204 | Успех без тела ответа | Удаление или обновление без response body |
| 400 | Некорректный запрос | Синтаксис или параметры не приняты |
| 401 | Требуется аутентификация | Нет валидных учётных данных |
| 403 | Доступ запрещён | У пользователя нет разрешения |
| 404 | Не найдено | Endpoint или ресурс не существует/недоступен |
| 409 | Конфликт | Конфликт состояния, например дубликат |
| 415 | Неподдерживаемый тип содержимого | Неверный Content-Type |
| 422 | Синтаксис принят, данные не проходят валидацию | Не допустимое значение поля |
| 429 | Слишком много запросов | Ограничение частоты запросов |
| 500 | Внутренняя ошибка сервера | Непредвиденная серверная проблема |
| 502/503 | Ошибка шлюза / сервис временно недоступен | Недоступная зависимость или обслуживание |

Коды в таблице объясняют распространённые значения, а не заменяют контракт конкретного API. Не считать 400, 401, 403 или 404 взаимозаменяемыми; проверять ровно то поведение, которое предусмотрено.

## Мини-чек-лист GET /products из этого проекта

- [ ] Метод `GET`, endpoint правильный.
- [ ] Статус `200`.
- [ ] `Content-Type` указывает на JSON.
- [ ] Тело ответа корректно разбирается как JSON-массив.
- [ ] Массив не пустой, если это ожидаемо для каталога.
- [ ] В каждом продукте есть обязательные поля.
- [ ] Типы ключевых полей проверены.
- [ ] Значения проходят базовые проверки.
- [ ] `id` уникальны, если это часть контракта.
- [ ] Фактический результат и доказательство сохранены.

## Мини-чек-лист POST /products из этого проекта

- [ ] Метод `POST`, endpoint правильный.
- [ ] `Content-Type: application/json`.
- [ ] Отправлен валидный JSON с тестовыми данными.
- [ ] Фактический статус зафиксирован и соответствует контракту.
- [ ] Тело ответа — корректный JSON-объект.
- [ ] Проверены поля, которые должны вернуться.
- [ ] Значения ответа сопоставлены с отправленным payload.
- [ ] Проверен ID, если его возвращение предусмотрено.
- [ ] Сохранены фактический результат и доказательство.
- [ ] Не утверждается постоянное сохранение записи только на основании успешного ответа Fake Store API.

## Как понять статус теста

- **Passed:** все проверки выполнены и ожидаемые условия соблюдены.
- **Failed:** проверка выполнена, но один или более ожидаемых результатов не совпали с фактическими.
- **Blocked:** выполнить проверку нельзя из-за окружения, доступа или недоступности зависимости.
- **Not run:** проверка ещё не выполнялась.

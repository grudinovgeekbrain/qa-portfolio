# Как устроен учебный проект

Документ для подготовки к собеседованию. Это обзор текущего кода, а не утверждение о коммерческом опыте.

## 1. Что лежит в основе

`web-testing/online_market.html` — одна HTML-страница. Внутри файла находятся три части:

- HTML — поле поиска, селект сортировки, область каталога и корзина;
- CSS — внешний вид элементов и карточек;
- JavaScript — загрузка товаров, поиск, сортировка, корзина и обработчики событий.

Отдельного backend в проекте нет. Каталог приходит из внешнего Fake Store API.

## 2. Основное состояние приложения

В начале JavaScript объявлены переменные:

- `originalProducts` — исходный массив товаров, полученный от API;
- `products` — список после фильтрации/сортировки, который показывается в каталоге;
- `cart` — товары в корзине;
- `searchQuery` — текущий поисковый запрос;
- `sortType` — выбранный вариант сортировки.

## 3. Загрузка каталога

`init()` запускает первоначальную инициализацию: сначала загружает корзину, затем отображает её, после чего вызывает `loadProducts()`.

`loadProducts()` использует `fetch()` для GET-запроса к `https://fakestoreapi.com/products`. При успешном ответе он разбирает JSON, сохраняет товары в `originalProducts` и вызывает `updateProducts()`. При ошибке показывает сообщение с предложением обновить страницу.

## 4. Поиск и сортировка

`updateProducts()` начинает работу с копии `originalProducts`, затем:

1. фильтрует массив по `searchQuery`, если строка поиска не пустая;
2. сортирует по цене, если выбрано `cheap` или `expensive`;
3. сохраняет результат в `products`;
4. вызывает `render(products)`, чтобы обновить DOM.

Поле поиска реагирует на событие `input`; селект сортировки — на `change`. Кнопка сброса очищает поиск и возвращает сортировку к значению по умолчанию.

## 5. Корзина и localStorage

- `loadCart()` читает сохранённое значение `cart` из `localStorage` и пытается разобрать его как JSON.
- `renderCart()` строит HTML корзины и считает итоговую стоимость.
- `saveAndRenderCart()` сохраняет состояние корзины и перерисовывает блок.
- Обработчик каталога добавляет товар в корзину или увеличивает количество существующей позиции.
- Обработчик корзины меняет количество, удаляет позицию или очищает корзину.

`localStorage` — хранилище браузера; данные переживают перезагрузку страницы в том же браузере и профиле.

## 6. Как это использовать в тестировании

Поскольку каталог, UI и корзина связаны друг с другом, проверяйте и отдельные действия, и их сочетания. Например, поиск → добавление товара → обновление страницы → проверка корзины. Для ошибок фиксируйте исходное состояние, точные шаги, ожидаемое и фактическое поведение, среду и доказательства.

## 7. Известные ограничения текущей версии

- Тесты Playwright в репозитории пока не настроены.
- Нет backend, собственной базы данных или реальной покупки/оплаты.
- Каталог зависит от доступности внешнего API.
- Тестовые статусы нельзя считать пройденными без фактического запуска и фиксации результата.
- В текущем коде заголовок товара имеет фиксированную высоту и `overflow: hidden`; это может обрезать длинные названия.

В проекте каталог загружается через `fetch`, а корзина хранится в `localStorage`. Сейчас я фиксирую результаты реального выполнения проверок и постепенно развиваю проект дальше».

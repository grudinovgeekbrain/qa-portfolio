# API-002 — Создание тестового товара

**Тип:** позитивный API-тест-кейс  
**Метод:** `POST`  
**Endpoint:** `https://fakestoreapi.com/products`  
**Приоритет:** Medium  
**Статус выполнения:** Not run

## Цель

Проверить, принимает ли API корректный JSON для создания тестового товара и возвращает ли ожидаемые данные в ответе.

## Предусловия

- Есть подключение к интернету.
- API доступен.
- Используется демонстрационный Fake Store API. Не считать успешный ответ доказательством долговременного сохранения товара в каталоге.

## Тестовые данные

```json
{
  "title": "QA Test Product",
  "price": 100,
  "description": "Test product created for API testing",
  "image": "https://i.pravatar.cc",
  "category": "electronics"
}
```

## Шаги

1. В Postman создать запрос `POST` к endpoint выше.
2. В `Headers` установить `Content-Type: application/json`.
3. Выбрать `Body` → `raw` → `JSON` и вставить тестовые данные.
4. Отправить запрос.
5. Зафиксировать HTTP-статус и тело ответа.
6. Проверить, что тело ответа является валидным JSON-объектом.
7. Проверить, что ответ содержит `title`, `price`, `description`, `image` и `category`, соответствующие отправленным значениям.
8. Проверить, что API вернул идентификатор созданного объекта, если это предусмотрено текущим ответом сервиса.

## Ожидаемый результат

- API возвращает успешный статус согласно контракту текущего сервиса.
- Ответ имеет корректный JSON-формат.
- Поля ответа соответствуют отправленным данным.
- Результат и фактический статус записаны в отчёте выполнения.

## Фактический результат

Не зафиксирован. После отправки запроса заполнить фактический статус, результат проверок и ссылку на доказательство.

## Отрицательные сценарии для дальнейшего расширения

- Отправить запрос без `title`.
- Передать строку вместо числового `price`.
- Отправить некорректный JSON.

Для каждого сценария сначала зафиксировать фактическое поведение API, затем сравнить его с документированным контрактом. Не придумывать ожидаемый статус без проверки документации.
